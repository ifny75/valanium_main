# valanium-onionize

Встроенный Tor для Valanium: локальный SOCKS5 поверх [Arti](https://gitlab.torproject.org/tpo/core/arti).

Скачали, положили рядом с приложением — Onion заработал. Ставить Tor Browser
или Orbot больше не нужно.

## Зачем отдельной программой

Клиент Valanium и так умеет ходить через SOCKS5 — так он работает с Tor Browser
и Orbot. Значит, чтобы Tor «просто был», достаточно поднять свой SOCKS5 рядом и
показать на него клиенту: **ни одной строки в сетевом слое менять не надо**.

Отдельная программа, а не часть приложения, по двум причинам. Tor остаётся вне
основной сборки — не везде его можно везти с собой, и не всем он нужен. И падение
Tor не роняет мессенджер: это отдельный процесс, его перезапуск ничего не рвёт.

## Запуск

```bash
valanium-onionize --data <каталог для состояния>
```

Печатает в stdout строку готовности:

```
READY 127.0.0.1:56569
```

До неё подключаться бессмысленно — цепь ещё строится. Приложение читает эту
строку, берёт из неё адрес и передаёт его клиенту как SOCKS5-прокси.

| Флаг | Что делает |
|---|---|
| `--data <путь>` | Обязателен. Куда класть состояние и кэш Tor. |
| `--socks <адрес>` | Необязателен. По умолчанию порт выбирает система. |
| `--allow-clearnet` | Разрешить не-onion адреса. По умолчанию запрещены. |

## Три решения, которые стоит понимать

**Порт по умолчанию выбирает система, а не мы.** Фиксированный номер здесь
вреден: 9050 занимает системный Tor, 9150 — Tor Browser. На машине, где они уже
стоят, мы бы либо не поднялись, либо увели чужой трафик. Настоящий адрес
печатается строкой `READY`, и приложение берёт его оттуда, а не угадывает.

**Каталог состояния задаётся снаружи, и это не удобство.** Arti по умолчанию
кладёт его в профиль пользователя, а там среди прочего живёт `guards.json` —
список входных узлов Tor этого человека. Постоянный след «пользовался Tor, вот
через кого» — ровно та метаданная, от которой Onion и должен защищать. Поэтому
путь передаёт вызывающий, и приложению следует класть его к себе, рядом с
остальными своими данными, а не в профиль. Замерено: каталог занимает около
45 МБ — заметно больше самого клиента.

**Только `.onion`.** Всякий, кто найдёт порт, иначе получил бы бесплатный выход
в интернет через Tor от нашего имени, и жалобы прилетели бы нам. Снимается
флагом `--allow-clearnet`, если однажды понадобится.

Слушаем при этом всегда только петлю: привязка к `0.0.0.0` превратила бы это в
открытый Tor-прокси для всей сети. Программа откажется стартовать, если ей
передать не-loopback адрес.

## Сколько это стоит по времени

Замерено на Windows, боевой onion-вход Valanium:

| | первый запуск | последующие |
|---|---|---|
| построение цепи | ~50 с | ~3 с |
| соединение с onion | ~8 с | ~7 с |
| **до первого байта** | **~58 с** | **~9 с** |

Отсюда следствие для интерфейса: **греть цепь надо в фоне при запуске
приложения**, а не по нажатию «Onion». Минута ожидания после нажатия читается
как «сломалось», и человек уйдёт раньше, чем оно заработает. Первый в жизни
запуск всё равно стоит около минуты, и это надо показать честным индикатором с
объяснением, а не крутилкой, неотличимой от зависания.

## Проверка

```bash
curl --socks5-hostname 127.0.0.1:<порт из READY> \
     http://<адрес>.onion/v1/health
```

Должно вернуться `{"ok":true,"v":1}`.

## Что обязано быть сделано до выкладки

Этот файл скачивается и запускается — значит, он **обязан быть подписан**, а
приложение обязано проверять подпись перед запуском. Скачивание и выполнение
неподписанного кода превращает удобство в удалённое выполнение кода: тот, кто
получит доступ к репозиторию или встанет посередине, получит его и на всех
машинах пользователей.

Подпись — тем же офлайновым ключом, которым подписываются релизы Valanium.
Механизм в приложении уже есть.
