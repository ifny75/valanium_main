# Valanium — архитектура

Документ описывает исходники мессенджера на 29 октября 2026 года, включая
одноразовую анонимную доставку, отдельные таймеры повторов и обмен пропусками.
Он не подтверждает версию работающего сервера или установленных приложений.
Архитектура VPN описана отдельно в `valanium-vpn-main/ARCHITECTURE.md`.

## 1. Принципы и граница доверия

Rust-ядро отвечает за ключи, MLS, шифрование локальных данных и сеть.
Android Java UI и Windows WebView получают открытый текст для отображения;
их безопасность зависит от целостности устройства и приложения.
Сервер и транспорт не получают ключи MLS личных бесед.

Ошибка подписи или некорректный протокольный кадр не служат основанием
отправлять открытый текст или переключать анонимную доставку на AUTH.
Секреты, содержимое сообщений и идентификаторы не нужны в журнале замеров.

## 2. Модель угроз и ограничения

| Данные или угроза | Механизм и предел защиты |
| --- | --- |
| Содержимое личной переписки и групп | MLS на клиентах; в очереди сервера — шифротексты |
| Украденная клиентская база | Запечатанные записи; защита зависит от ключа базы и платформенного хранилища |
| Подмена ключа собеседника | Закрепление ключей и ручная сверка отпечатка/QR; первый контакт требует проверки |
| IP клиента на onion-входе | SOCKS5/Tor, имя `.onion` не отправляется в системный DNS |
| Личность анонимной отправки | Отдельное onion-соединение без AUTH; билет и пропуск предъявляются там |
| Сетевые метаданные | Размеры, время и адрес получателя остаются наблюдаемыми; корреляция по времени возможна |
| Открытые каналы | Посты не являются личной MLS-перепиской, сервер обрабатывает их содержимое |
| Поддержка | Отдельная база, сообщения поддержки доступны серверной стороне |

Root, вредоносный клиент, кейлоггер и снятие текста с экрана находятся за
пределами криптографической защиты. Отсутствие поля отправителя в очереди
не означает, что оператор сервера не способен наблюдать активные соединения.

## 3. Компоненты и репозитории

| Компонент | Ответственность | Источники |
| --- | --- | --- |
| Ядро | MLS, ключи, команды/события, хранение, транспорт | `valanium-core/src` |
| Android | Java UI, JNI, foreground-сервис, Keystore, Tor | `valanium-android` |
| Windows | WebView2, Tauri, системное хранение и интеграция | `valanium-windows` |
| Релей | WebSocket, AUTH, билеты, пропуска, очередь, ACK/TTL | `valanium-server/src` |
| Развёртывание | Onion/HTTPS-входы, nginx, WireGuard, systemd | `deploy` |

`valanium_main` содержит все компоненты. Отдельные репозитории
`ifny75/valanium_android`, `ifny75/valanium_pc` и `ifny75/valanium_server`
обновляются независимо. В отдельных клиентах ядро — git-зависимость с
конкретным SHA; в монорепозитории — локальная path-зависимость.
Нельзя определять совместимость установленной сборки только по ветке `main`.

Android передаёт JSON-команды через JNI и забирает события фоновым опросом.
Windows линкует ядро напрямую, а UI общается с Rust через Tauri.
C API ядра: `obs_init`, `obs_send`, `obs_poll`, `obs_free`, `obs_shutdown`.
Точный словарь команд и событий — `valanium-core/src/command.rs`.

## 4. Личность и восстановление

Личность и устройство имеют ключи Ed25519; сертификат устройства подписан
ключом личности. Клиент доказывает владение ключом по одноразовому nonce.
Текущий клиент использует фразу из 24 слов для восстановления личности.
Она не восстанавливает утраченную локальную историю автоматически.

Исторические команды поиска по username, восстановления по логину/паролю
и TOTP остались в отдельных структурах протокола и серверном коде. Клиент
отклоняет старые команды входа/восстановления ответом `seed_only`.
Это код совместимости, а не действующий пользовательский способ входа.

## 5. Шифрование и хранилище

MLS реализован через OpenMLS. Изменение состава группы и обновления ключей
меняют эпоху. Проверки состава и принадлежности ключей выполняются в ядре.

Локальные записи защищены XChaCha20-Poly1305; для выведения ключей
применяется Argon2id. На Android локальный секрет защищён Android Keystore.
Конкретные платформенные ключи и миграции описаны в README клиентов.
Сервер не хранит ключ расшифровки личных сообщений.

Модули: `mls.rs`, `keys.rs`, `crypto.rs`, `store.rs`, `padding.rs`, `pins.rs`.

## 6. Основная сессия

Основной WebSocket получает HELLO, проходит AUTH и обслуживает входящую
очередь, публикацию/получение KeyPackages, выдачу билетов и команды аккаунта.
`HELLO.features` определяет доступные расширения; клиент не должен
посылать неизвестные серверу опкоды наугад.

Heartbeat поддерживает соединение и не задаёт срок повторной анонимной отправки.
ACK входящего конверта удаляет его из серверной очереди с проверкой получателя.
Отсутствие ACK допускает повторную доставку: обработка должна учитывать дубликаты.

## 7. Wire-протокол

Кадр начинается с опкода, затем следует бинарное или JSON-тело.
Единственный поддерживаемый формат определяется парсерами, а не этой таблицей:

- Rust: `valanium-core/src/proto.rs`;
- сервер: `valanium-server/src/proto/frames.ts`;
- обработчики: `valanium-server/src/ws/session.ts`.

| Группа | Примеры кадров |
| --- | --- |
| Сессия | HELLO, AUTH, AUTH_OK, PING/PONG, ERROR |
| Доставка | SEND, SEND_ANON, SEND_OK, ENVELOPE, ACK, QUEUE_DONE |
| MLS | KEYPKG_PUBLISH, KEYPKG_CLAIM, KEYPKG |
| Анонимность | TICKET_REQUEST, TICKET_GRANT |
| Входящий доступ | ACCESS_SET, PASS_CREATE, PASS_PRESENT, PASS_REVOKE |

### 7a. Sealed sender и очередь клиента

Основная аутентифицированная сессия запрашивает пачку одноразовых билетов.
Анонимная отправка использует отдельный onion-WebSocket: HELLO,
при необходимости PASS_PRESENT, затем SEND_ANON и ожидание SEND_OK.
На этом сокете нет AUTH и второго сообщения. Изоляция Tor сохраняется.

Ядро может заранее подготовить до двух таких сокетов без личности, получателя,
билета и содержимого. Перед использованием проверяется его возраст;
после 45 секунд сокет отбрасывается. Завершение подготовки сразу будит очередь;
она не запускает конкурирующее холодное соединение, пока строится готовящееся.
Ошибка подготовки освобождает слот с паузой перед повтором. Подготовка и
полная попытка отправки ограничены 25 секундами, TTL может сократить ожидание.
При отсутствии готового сокета сообщение ждёт обычного подключения через Tor.

Перед отправкой удаляются просроченные билеты и билеты с остатком жизни
не более 30 секунд. Одна пачка запрашивается за раз, с отдельным десятисекундным
дедлайном повтора. Подпись проверяет сервер; локальное время клиента должно
быть корректным. Запас ограничен 32 билетами.

Шифротекст, `client_ref` и состояние MLS сохраняются атомарно в запечатанную
локальную очередь (`anon_queue.rs`). Подтверждение SEND_OK снимает конверт
с очереди. При ошибке повторяется тот же шифротекст и ссылка; серверная
дедупликация защищает от повторной постановки после потери ответа.

Повторы имеют отдельные дедлайны: 2, 4, затем 8 секунд. Один медленный
получатель не задерживает остальных. Одновременно активны не более четырёх
отправок и не более одной на устройство; Welcome/commit предшествуют
зависимым сообщениям. Неудачный onion-вход временно исключается на 30 секунд,
если известен другой доступный кандидат. Состояние выбора хранится в памяти.

В анонимном режиме обычные, служебные и групповые конверты проходят очередь
без резервного SEND через AUTH. При обычной политике доставки основной
аутентифицированный SEND остаётся отдельным предусмотренным путём.

SEND_OK означает принятие сервером. Прочтение и доставка адресату — другие
состояния; их нельзя выводить из длительности установки соединения.

## 8. Данные сервера

SQLite хранит устройства, сертификаты, инвайты, KeyPackages, конверты,
политику доступа, хеши пропусков и данные дедупликации. Схема и миграции:
`valanium-server/src/db/schema.ts`, `db/index.ts`.

Конверты ограничены TTL, числом и суммарным объёмом очереди. ACK проверяет
принадлежность устройству. Сервер выдаёт порции до 200 конвертов, ждёт их ACK
и продолжает следующую порцию без переподключения. При backpressure выдача
возобновляется обработчиком `drain`, а не переполняет буфер сокета.

Данные поддержки находятся отдельно. Публичные каналы, профили и код
совместимости восстановления имеют собственные таблицы; их наличие
не делает эти данные личной MLS-перепиской.

## 9. Вложения, каналы и HTTP

Фотографии и голосовые сообщения в личных беседах обрабатываются клиентом
как зашифрованное содержимое. Старых HTTP API загрузки/скачивания blobs нет.
Каталог blobs в конфигурации не доказывает наличие работающего файлового API.
Публичные каналы имеют отдельные команды и не обещают E2EE их публикаций.

Текущие HTTP-маршруты:

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET | `/v1/health` | Проверка живости |
| GET | `/v1/releases/latest` | Метаданные сборок |
| POST | `/v1/support/inbound` | Отдельный Bearer-секрет входящей поддержки |

Общий HTTP Bearer для сообщений и вложений не выдаётся.
Источник: `valanium-server/src/http/routes.ts`.

## 10. Доступ и пропуска

Инвайт разрешает регистрацию, билет — анонимную попытку, пропуск — входящее
сообщение конкретному получателю. Это три разных механизма.
Сервер хранит хеш пропуска и владельца; предъявленный секрет создаёт допуск
в памяти текущего соединения. Анонимный onion-сокет может предъявить пропуск
без AUTH при поддержке `sealedSenderPasses` в HELLO.

Пропуска знакомым передаются служебными MLS-сообщениями, в том числе при
появлении новой беседы. Перед первым включением ограничений ядро проверяет
взаимные пропуска у существующих разрешённых контактов и отсутствие
неотправленных essential-конвертов. При незавершённом обмене возвращается
`privacy_pass_exchange_pending`; новые настройки не записываются.

Уже ограниченная учётная запись не открывается автоматически. Если оба
контакта ранее закрыли приём без взаимных пропусков, нужны приглашения,
переданные вне заблокированного чата. Переключение такого аккаунта на onion
остаётся доступным. Реализация: `access.rs`, `client.rs`, серверный `ws/session.ts`.

## 11. Транспорт и развёртывание

Onion-имя передаётся SOCKS5 без системного DNS. Встроенный Tor и внешний
SOCKS-прокси зависят от платформы и сборки. Каждый анонимный сокет сохраняет
отдельную изоляцию; постоянный сокет на несколько отправок не используется.

Код маршрутизации ядра использует основной relay и onion-входы; старый
Multi-hop нельзя считать доступным по наличию строк в интерфейсе или старых
конфигов. Auto и Onion разворачиваются в маршруты в `client.rs`.
Полученные onion-адреса проверяются по подписанным данным HELLO и дополняются
встроенными запасными адресами.

В поставляемой схеме входные nginx/Tor-узлы доставляют WebSocket основному
серверу через WireGuard. Настройка узлов: `deploy/README.md`, `deploy/mesh/README.md`.
Состояние этих конфигов не является измерением работающей сети.

## 12. Интерфейсы и жизненный цикл

Android foreground-сервис поддерживает работу ядра, но ограничения ОС,
энергосбережение и отсутствие сети могут задержать доставку.
Windows использует WebView2 и платформенную обвязку Tauri.

Свайп сообщений направлен к центру: исходящие влево, входящие вправо.
Контейнер Android занимает всю строку. Выбор действия зависит от расстояния
жеста, а видимое смещение пузыря отдельно ограничено границами строки.
Поэтому длинный текст не обрезается, а короткий входящий пузырь не ограничивает
область жеста своей шириной. Отмена не выполняет действие; вертикальное
движение остаётся прокруткой. Входящее сообщение не получает действие правки.

## 13. Проверки и диагностика

- `cargo test --manifest-path valanium-core/Cargo.toml --lib` — ядро.
- `npm run check` и `npm test` в `valanium-server` — сервер.
- `npm test` в `valanium-windows` — поведение pointer-жестов.
- `MessageSwipeTest` — логика и границы свайпа; `MessageInteractionDeviceTest`
  — измерение реальных View в изолированном Android QA-приложении.

`VALANIUM_DELIVERY_TIMINGS=1` включает локальные длительности подключения,
HELLO и серверного ACK без идентификаторов. Это не замер доставки собеседнику.
Старый интеграционный тест восстановления по паролю ожидает снятый механизм
и падает с `seed_only`; это ограничение текущего набора тестов.

## 14. Обновление компонентов

Обновляйте совместимые сервер и ядро. В отдельных клиентах меняйте SHA
в манифесте и lockfile вместе. Сверяйте копии исправлений интерфейсов в
монорепозитории и отдельных Android/Windows-репозиториях. Git push не
перезапускает сервер и не заменяет установленные APK/Windows-приложения.

## 15. Практические пределы

Прогрев и быстрые повторы уменьшают локальное ожидание, но не гарантируют
латентность Tor. Проверка на двух реальных устройствах, подпись APK,
сборка Windows и проверка сетевого развёртывания — самостоятельные этапы.
Лицензия проекта — GNU AGPL v3; сторонние зависимости и товарные знаки
регулируются своими файлами лицензирования.
