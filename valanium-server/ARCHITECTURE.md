# Архитектура релея Valanium

Состояние исходников: 29 октября 2026 года. Релей работает на Node.js 24+,
TypeScript, uWebSockets.js и встроенной SQLite (`node:sqlite`).

## Слои

| Источник | Ответственность |
| --- | --- |
| `src/index.ts` | Запуск, WS callbacks, HTTP, периодическая очистка |
| `src/ws/session.ts` | HELLO, AUTH, SEND/SEND_ANON, ACK, пропуска |
| `src/ws/registry.ts` | Активные получатели в памяти |
| `src/auth/tickets.ts` | Подпись и погашение одноразовых билетов |
| `src/db/schema.ts`, `src/db/index.ts` | Миграции, конверты, TTL, дедупликация |
| `src/http/routes.ts` | Health, сведения о релизе, входящая поддержка |
| `src/support` | Отдельная база поддержки |

## Доставка

Основная сессия проходит AUTH и получает очередь, KeyPackages и билеты.
SEND_ANON принимается на отдельном onion-соединении без AUTH. Если получатель
требует пропуск, PASS_PRESENT предъявляется на этом же соединении.
Фичи `sealedSender` и `sealedSenderPasses` объявляются в HELLO.

Сервер проверяет билет, получателя, допуск и квоты до постановки в очередь.
Дедупликация повторов позволяет повторить тот же шифротекст и client_ref
при потере SEND_OK. ACK удаляет только конверт своего устройства.

Очередь выдаётся порциями до 200 конвертов. После ACK всей выданной порции
отправляется следующая; дубликаты ACK не запускают повторную выдачу порции.
Backpressure останавливает отправку, callback `drain` продолжает её.
Подключение не нужно разрывать для получения остатка очереди.

## Доступ и наблюдаемость

Инвайт регистрации, билет анонимной отправки и пропуск получателя имеют разные
назначения. Допуск по предъявленному пропуску хранится в памяти соединения;
серверная запись содержит хеш пропуска и владельца.
Релей не имеет ключей MLS личных бесед. Адрес получателя, длина и время
конверта остаются наблюдаемыми; AUTH раскрывает личность основной сессии.
Каналы и поддержка не являются личной MLS-перепиской.

В серверном дереве сохранены исторические обработчики восстановления и TON.
Они не означают, что текущий клиент включает вход по паролю: ядро использует
seed-фразу и возвращает `seed_only` для старых команд. TON опционален и
включается только конфигурацией. Не публикуйте секреты конфигурации в логах.

## HTTP и развёртывание

GET `/v1/health`, GET `/v1/releases/latest` и POST `/v1/support/inbound`.
Последний требует отдельный Bearer-секрет поддержки. Общего HTTP API сообщений
или загрузки blobs нет. WebSocket-входы и WireGuard описаны в `../deploy/README.md`.
Запуск с HTTPS/onion и фактическая сетевая доступность зависят от конфигурации.

## Проверки

`npm run check`, `npm test`, `npm run smoke`. Тесты проверяют анонимные
пропуска, дедупликацию, квоты, ACK, очередь больше 200 и backpressure.
Изменение исходников не обновляет работающий процесс: развёртывание отдельно.
