# Приватность: второй этап

## Профиль для существующего аккаунта

В Android 0.7.7 и исходниках Windows в разделе «Приватность» добавлена кнопка «Применить к этому аккаунту». Она посылает одну локальную команду `privacy_maximize`; преобразование правил выполняется общим ядром. Обычный ответ `privacy` не считается подтверждением применения: для этого есть отдельное событие `privacy_maximized`.

Профиль выключает presence, last_seen, read_receipts, typing, voice_recording_hint, link_previews, поиск по имени, показ юзернейма и будущие звонки. Для личных сообщений и вложений остаются одобренные собеседники; имя и аватар ограничиваются контактами. Обход запросов по приглашению отключается. Разрешающие исключения очищаются, явные запреты сохраняются. Применение идемпотентно; после него каждое правило можно настроить отдельно.

Правила сохраняются без подключения. Активная сессия закрывается, приложение выбирает Onion. Настройка скрытия скриншотов, пароль и другие локальные предпочтения не изменяются. Поиск и пропускная политика сервера синхронизируются после аутентификации, а также при последующих правках правил; при недоступной сети серверные изменения ожидают подключения. Хеш имени обновляется тем же механизмом с отслеживанием подтверждения, чтобы параллельная старая миграция не вернула публичную видимость.

## Единая доставка зашифрованных конвертов

Для Onion общая сохранённая политика доставки распространяется на личные сообщения, Welcome, коммиты MLS, описания групп, групповые сообщения, пропуска, ключи профиля и объявления устройств. Служебные вызовы без контекста личного сообщения больше не обходят анонимную очередь. Явный Relay/Auto остаётся отдельным выбором пользователя; уже сохранённые анонимные конверты не переводятся на авторизованную отправку.

Групповой fan-out добавляется в очередь одной записью настройки: если пакет не помещается в лимиты, в очередь не попадёт только часть получателей. Требуемые Welcome/коммиты отмечены отдельно от пользовательских сообщений. Очистка локальной истории их сохраняет; явное удаление беседы отменяет и их. При этом атомарность добавления в очередь не является общей транзакцией изменения состояния MLS и всех записей истории.

Одновременно отправляется не более четырёх конвертов разным устройствам. Для каждого устройства следующий конверт запускается после подтверждения предыдущего. Это сохраняет порядок Welcome → коммит → сообщение при повторах и после перезапуска.

Набор текста, присутствие и подтверждения прочтения проверяются также ядром до шифрования, а не только интерфейсом. При разрешённой отправке такие сигналы имеют ограниченный срок жизни; устаревшие записи удаляются, а время активной попытки ограничивается сроком сигнала. Максимальный профиль удаляет ожидающие сигналы активности. Идентификаторы сообщений извлекаются также из клиентского формата `OBS1`, чтобы отмена ожидающих сообщений работала с реальным форматом обоих клиентов.

## Границы защиты

Сервер по-прежнему видит получателей, времена, размеры, аутентифицированное получение сообщений и запросы KeyPackage. Одинаковый групповой MLS-шифротекст пока можно сопоставить между получателями: этот этап убирает авторизованного отправителя из доставки таких конвертов, но не устраняет корреляцию группового fan-out. Нет обещания защиты от глобального наблюдателя и анализа времени.

Публичные каналы остаются публичными. Уже раскрытые имя, аватар и другие сведения нельзя отозвать у наблюдателя; изменение правила не является ретроактивным стиранием ранее опубликованных данных. Скрытие поиска работает в рамках честного исполнения политики сервером.

## Проверки

Тесты проверяют сохранение запретов и очистку разрешающих исключений, повторное применение профиля, ошибку на повреждённом документе, запрет read/typing в ядре, совместимость старой очереди, атомарный отказ переполненного fan-out, сроки активности, сохранение обязательных коммитов и порядок по устройству.

В тесте с тремя MLS-участниками Welcome и групповой payload попадают в очередь без SEND на авторизованном сокете; оба получателя расшифровывают сообщение после Welcome. Это локальная проверка протокольного пути, а не проверка живого группового обмена через Tor.

Изолированная проверка Android применяет профиль к ранее разрешающему документу через реальную кнопку и команду JNI; основной аккаунт не изменяется тестом. Windows проверяет, что переподключение запускается только после специального подтверждения профиля.
