# Аккаунт по сид-фразе

Android 0.7.9 и Windows 0.13.6 создают аккаунты без имени пользователя, логина и пароля восстановления. Для восстановления используется сид-фраза BIP39 из 24 слов. Контакты добавляются по коду OBS или адресу устройства; поиск в списке чатов остаётся локальным. Имена публичных каналов — отдельная функция и сохраняются.

После новой регистрации Android предлагает сохранить фразу, Windows открывает мастер сохранения. В обоих клиентах фразу можно снова открыть в настройках безопасности. Не публикуйте её в отчётах, скриншотах и логах.

Общее ядро отклоняет `username_set`, `username_lookup`, `recovery_setup`, `recover_password`, `totp_secret` локально, как до соединения, так и во время него. Регистрация отправляет `handle: null`. При синхронизации старое имя переводится в скрытый режим без освобождения владельца имени. Шифрование базы и ключи существующих аккаунтов сохраняются; новый аккаунт при обновлении не создаётся.

Пароль старой локальной базы при её однократном переносе, отдельная блокировка Windows и пароль зашифрованного архива относятся к защите данных на устройстве, а не ко входу в аккаунт, и сохраняются. Новый внутренний ключ базы создаётся автоматически и защищается системным хранилищем.

Старые серверные записи совместимы с прежними клиентами: обновление не удаляет ранее созданные зашифрованные резервные копии и не отключает предыдущие версии приложения на сервере. Для полного удаления старых способов восстановления нужна отдельная миграция сервера и явное управление существующими резервными копиями.

Проверки: тест ядра запрещает все пять устаревших команд без изменения личности и проверяет восстановление той же личности по 24 словам в пустую базу. Windows-тесты проверяют регистрацию без полей учётных данных, отказ без обхода Tor и требование всех 24 слов. Сборка Android проверяет ссылки ресурсов и Java/JNI, обычные JUnit-тесты запускаются без телефона. Работа Android на устройстве в этой итерации не проверялась по просьбе пользователя.
