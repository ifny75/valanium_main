# Delivery stability and recovery

The client no longer treats a successful WebSocket write as delivery. Auto/Relay messages, Welcome frames, and epoch commits now use the existing encrypted durable queue, preserving ciphertext and client reference through disconnect/restart until the matching server ACK. A 45-second missing-ACK deadline reconnects even when heartbeat replies continue. Legacy/onion queue entries cannot use the authenticated route; explicit relay-created entries may switch to anonymous delivery after selecting Onion.

Scheduled rotation occurs after the server backlog's QUEUE_DONE, only on the lowest device key in the group's authenticated membership, and while the group has no queued envelopes. This avoids simultaneous periodic commits by both peers. The commit, saved MLS state, and queue insertion are transactional, with in-memory state restored on failure. Both clients must update for the single-initiator rule to cover the pair. Group membership changes are separate explicit operations.

OpenMLS previously retained zero previous epochs despite the old source comment claiming otherwise. New and loaded groups now retain three previous epochs, allowing bounded late-message delivery across rotation. This deliberately retains those old application secrets longer; it does not restore secrets already discarded by older builds.

First-contact sends awaiting a KeyPackage are persisted in the encrypted database, bounded to 128 intents / 16 MiB. Only one claim per device is in flight. Empty responses retry on heartbeat; missing responses force reconnect after 45 seconds. Welcome, channel mapping, MLS snapshot and first payload are committed together. Diagnostic pending counts include these intents so background jobs do not finish early.

Both clients expose **Repair delivery** in a contact's actions. This local, explicit action requests a new KeyPackage for the same device, verifies the existing device binding and pin constraints, and attaches the new encrypted group to the existing history thread. It keeps account identity and local history. It does not unblock peers or approve changed keys. Decrypt failures from the network do not trigger resets. Old unread ciphertext with lost epoch keys may need to be resent; repairing cannot retroactively decrypt it.

Validation includes exact relay retransmission/ACK, missing ACK with live heartbeat, first-contact empty key response and replay, queue-full rotation rollback, single rotation initiator, previous-epoch decryption after reopen, and repair of an intentionally diverged channel without identity/history loss. Real Pixel QA uses disposable accounts and exercises Tor, repair, network reconnect, profile updates, verification QR pairing and Auto delivery. User account data is not reset.
