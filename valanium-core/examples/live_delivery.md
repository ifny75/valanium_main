# Проверка доставки через Tor

`live_delivery` создаёт два тестовых аккаунта и отдельные зашифрованные базы
в новом каталоге. Он работает с настоящим сервером, поэтому запускать его
следует осознанно, для проверки живой доставки. Данные пользовательского
аккаунта не используются; ключи и содержимое сообщений в журнал не выводятся.

```powershell
cargo run --manifest-path valanium-core/Cargo.toml --example live_delivery -- <new-qa-directory> <local-socks-host:port>
```

Проверяются первое сообщение, ответ, расшифровка получателем и подтверждение
сервера. Для повторного запуска с теми же тестовыми аккаунтами есть `--resume`.

`--maximum-privacy` дополнительно включает максимальную приватность у обоих
клиентов и проверяет доставку после переподключения. Этот сценарий пока имеет
известный дефект: без заранее обменённых пропусков оба клиента могут закрыть
входящие сообщения раньше, чем доставят друг другу сами пропуска. В проверке
28 октября 2026 года обычная доставка через Tor в обе стороны прошла, а эта
фаза завершилась `anonymous_delivery_waiting` и таймаутом. Исправление формы
отправки Windows 0.13.8 этот дефект ядра не устраняет.

Будущее исправление должно сохранять запрет посторонних сообщений и анонимную
отправку: переход на открытый вход или отправку через аутентифицированное
соединение не является исправлением этого сценария.
